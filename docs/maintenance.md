# Maintenance planning

ChargeTrackr separates a maintenance plan from the work order that a technician executes:

- `MaintenancePlan` stores the station, optional connector, type, priority, technician, instructions and recurrence rule.
- `Intervention` represents one dated occurrence generated by that plan.
- Alert-based corrective interventions continue to use the same work-order workflow without requiring a maintenance plan.

## Lifecycle

1. An administrator or operator creates a one-time or recurring plan.
2. The first occurrence is created synchronously. `GenerateMaintenanceOccurrences` generates the following 90-day window through the Laravel queue.
3. A planned occurrence does not alter station availability.
4. Only its assigned technician can move it to `in-progress`.
5. Starting an occurrence applies the maintenance override immediately. For a connected OCPP station, `ChangeAvailability(Inoperative)` is queued for connector `0`.
6. Completing or cancelling active work clears the owned override. For a connected OCPP station, `ChangeAvailability(Operative)` is queued.
7. A station cannot run two active maintenance occurrences, and a manually controlled maintenance override must be cleared before planned work starts.

Paused work and work waiting for parts remain in maintenance mode. Cancelling a future occurrence does not cancel the rest of a recurring series.

## Recurrence

Supported frequencies are one time, daily, weekly and monthly, with an interval and optional end date. Each generated occurrence has a deterministic plan sequence and a database uniqueness constraint. Generation locks the plan before advancing `next_occurrence_at`, so retries cannot create duplicates.

The scheduler dispatches the generation job hourly:

```text
GenerateMaintenanceOccurrences -> MaintenancePlanService::generateUpcoming()
```

## API

- `GET /api/maintenances`: scoped occurrences, summary, station options and technician options.
- `POST /api/maintenances`: create a plan and its first occurrence.
- `PATCH /api/maintenances/{occurrence}`: reassign or reschedule planned work.
- `PATCH /api/interventions/{occurrence}`: execute controlled lifecycle transitions.

Permissions are split between `maintenances.view` and `maintenances.manage`. Technicians only see work assigned to them; administrators and operators are restricted to their organization.

## User interfaces

- `/maintenance`: summary, search, filters, table and monthly calendar.
- Maintenance drawer: station, connector, technician, schedule, duration, instructions and recurrence.
- Station detail: real maintenance history and schedule filtered by station.
- Technician interventions: generated occurrences use the existing assignment and execution workflow.
